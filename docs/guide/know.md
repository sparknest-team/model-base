# 核心概念：结构、数据、保存点

## 三种东西不要混在一起

| 概念 | 保存什么 | 什么时候改变 |
|---|---|---|
| 列定义（Column） | 字段名、映射、默认值、子模型等规则 | 定义类或注册字段时 |
| 模型实例 | 当前业务值 | 赋值、更新、还原时 |
| 保存点 | 用于比较和还原的数据基准 | 创建、保存或部分回填操作时 |

给 `user.displayName` 赋值不会修改列定义。调用 `saveChangedData()` 也不等于向服务器发请求。

## 数据流

`DTO → 创建/反序列化 → 模型实例 → 序列化 → DTO`

DTO 是传输用的普通对象。模型实例则有方法、子模型和可选的变更追踪。
默认输入接受蛇形与驼峰名称，默认输出使用蛇形；严格字段名请查看 [name](/column/name/)。

## 类型与校验

`name!: string` 是 TypeScript 声明，不会把任意输入自动变成字符串，也不会拒绝无效输入。
`type` 不是通用强制转换器；使用 `deserialize` 明确转换，并在业务层完成校验。

## 保存点不是始终存在的完整副本

标准静态模型树使用延迟快照：初始化建立保存点关系，首次写入记录旧值，查询时按需生成旧 DTO。
自定义序列化、访问器、数据驱动列等保留即时快照路径。不要依据是否存在内部 `__CLONE__` 条目判断变更。

`getOriginalData()` 返回可变的基准 DTO，不是每次创建副本；修改它会影响后续比较和还原。

## 配置作用域

实例配置 > 类配置 > 库默认值。创建参数影响本次模型树，不修改全局或其他 npm 包的模型。

```ts
const user = User.create(dto, { enableSnapshot: false, noDefault: true })
```

这里的 User 使用[入门模型](/guide/start/)，dto 表示业务输入。
`enableDataState` 是 `enableSnapshot` 的兼容别名，同一层新名称优先。
